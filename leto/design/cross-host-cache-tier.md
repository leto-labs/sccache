# Cross-host sccache tier

**Later.** Keep the 300 GiB local caches and main pre-warm on each project’s current host. Revisit when a project regularly builds on two hosts or trusted CI workers repeatedly start cold. Dependencies can hit across hosts today, but the observed key overlap is small. Local pre-warm already covers main on the host where it will be built, including workspace crates that the other hosts never produce.

The last column joins distinct registry and Git dependency keys in up to 10,000 existing Rust miss records per host on Nov 21, 2026, around 01:12–02:42 UTC. Project attribution uses checkout basedirs. There were 58 distinct shared keys, or **0.05–4.5% of sampled Rust miss keys per project** when workspace keys are included. The sample spans rollout churn and mixed build lanes. It omits local hits and gives no evidence of which misses produced retained entries.

All projects pin Rust 1.99.1. All hosts report commit `58cf8f9c3`, target `x86_64-unknown-linux-gnu` and the same rustc driver digest. Core’s contract aligns dev/test profiles, default linker selection and checkout remapping. Feature sets, rustflags, profile and emit mode, Cargo metadata, dependency bytes and generated or native inputs still affect keys. Semantic mode excludes `CARGO_TARGET_DIR` itself, while paths outside basedirs such as an external `OUT_DIR` or a different registry root can matter. Incremental sessions stay local and can bypass cache lookups. Linked targets also key on linker identity, search paths and verbatim values read by `env!`. ## Cost and expected saving

- Direct tailnet pings were about 1 ms on all three pairs. One 256 KiB random SSH transfer per direction gave **43–54 MiB/s from devbox to the workers**, **16–20 MiB/s toward devbox** and **26–54 MiB/s between workers**, excluding SSH setup. Bulk throughput, contention and WebDAV response times remain unmeasured. Relayed paths can be slower. [Tailscale connection types](https://tailscale.com/docs/reference/connection-types).
- At 16–54 MiB/s, **20 MiB costs 0.4–1.3 s**, **600 MiB costs 11–38 s**, and **1 GiB costs 19–64 s** in transfer alone. Use compressed wire size for those estimates. Linked outputs in the 20–600 MB range add decompression, verification and writes, and the current default cap skips entries over **256 MiB uncompressed**. The remote backend buffers the full response. [Linked-output cap](../../docs/Rust.md#linked-outputs), [remote storage](../../src/cache/storage.rs).
- At equal compile cost per unit, the observed match fraction would save roughly **0–5% of cacheable Rust compile time** across different projects, before I/O. Matches include many small utilities and macros, and there are no per-key timings. Ten 2 MiB hits at 0.5–2 s of avoided compile time each would save 5–20 compiler-seconds and take 0.4–1.3 s to transfer. Wall savings depend on the critical path and extra L1 misses.
- A move, wipe or cold CI run of the **same project** can reuse workspace entries as well as dependencies. As an indication of scale, Core recorded 394 s on Longbow’s first clone and 255 s on a second clone with the local cache warm. A remote tier can recover some of that gap if the same workload and keys are present. Each GiB fetched from devbox would add roughly 19–24 s at the observed downstream rates, before restore costs. All four pre-warm timers were active when checked. [Core measurement log](../../../core/docs/infrastructure/2026-11-20-rust-build-master-plan.md), [pre-warm](../prewarm/README.md).

## Smallest pilot when demand repeats

Serve a separate, quota-limited WebDAV directory on devbox over the tailnet. Set `SCCACHE_MULTILEVEL_CHAIN=disk,webdav`, `SCCACHE_MULTILEVEL_WRITE_ERROR_POLICY=l0`, the WebDAV endpoint and a shared key prefix. Populate L1 by pre-warming a representative lane with an empty pilot L0. Give consumers read-only credentials and set `SCCACHE_WEBDAV_RW_MODE=READ_ONLY` where practical. A compatible GET/PUT service can use the WebDAV adapter with precreated paths and directory creation disabled. Redis uses RAM and defaults to a 512 MB value limit. Worker peering adds endpoints and duplicate uploads. [WebDAV](../../docs/Webdav.md), [Redis strings](https://redis.io/docs/latest/develop/data-types/strings/).

The chain reads L0 then L1 on a miss or read error and backfills L0 asynchronously. `l0` waits for disk and publishes remotely in the background. `ignore` backgrounds writes at every level. `all` waits for writable levels and reports failures. After validating the endpoint, `SCCACHE_SKIP_CACHE_CHECK=true` avoids a synchronous remote probe before background writes. Shorten the default 60 s lookup deadline for a small-entry pilot and track accepted hits, lookup latency and wall time. [Multilevel code](../../src/cache/multilevel.rs), [configuration](../../docs/Configuration.md), [lookup and verification](../../src/compiler/compiler.rs).

An ext4 pilot needs no fork change. The multilevel path disables reflinks on btrfs and writes compressed entries. Before enrolling btrfs workers, retain file-backed L0 hits through IPC, aligned raw writes and `user.sccache.weight` accounting at L0. Publish compressed entries to L1 with size and concurrency limits. Backfill can start compressed. Exclude large linked entries from L1 initially. Sysroot-relative and basedir-relative inputs resolve locally. Absolute libraries or search-directory timestamps and contents can fail verification on another host. Tier hit counters and backfill precede verification. Use accepted compiler hits, miss-explain for key differences and debug logs for manifest rejections. Restrict the endpoint to trusted hosts and writers. Cached executables and proc macros can run downstream, so isolate untrusted CI from this namespace. [Storage selection](../../src/cache/cache.rs), [local weights](../../docs/Local.md#reflink-cache-hits), [link manifests](../../src/compiler/rust/linked.rs).

For a one-off move or wipe, pre-warm the destination with the usual commands, or accept one cold build. A wipe at the same tip needs a fresh pre-warm marker and build state that actually invokes the compiler. If recovery time matters, rsync a trusted, quiescent cache snapshot into the destination before its server indexes it. Preserve mtimes and compatible weight xattrs, leave out logs and temp files, and use a raw-capable fork for raw entries. A 300 GiB payload would take roughly **1.6–5.3 hours** at the observed rates, and a weighted btrfs cache can have more logical bytes than its limit. A targeted seed or local pre-warm is usually cheaper. [Pre-warm runner](../prewarm/prewarm.py), [disk cache index](../../src/lru_disk_cache/mod.rs).
